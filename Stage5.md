# Results Summary and Lessons Learned

## Project: Ammar Platform

---

## Results Summary

The main objective of the Ammar Platform was to simplify the process of finding reliable engineering and construction companies that match the client's needs, requirements, and budget. The project aimed to make the first and most important step of any construction project easier by providing users with a centralized platform to explore and compare available service providers.

The final MVP successfully achieved the core objectives defined at the beginning of the project. The platform allows users to browse companies, view company information, compare available options, and identify suitable service providers based on their needs. The system also provides an organized and user-friendly interface that improves the process of connecting clients with construction companies.

The MVP included the following core functionalities:

* User registration and authentication
* Company profile management
* Service browsing and search functionality
* Project request and booking workflows
* Project updates and tracking
* Review and rating features
* Responsive user interface

### Comparison to Initial Objectives

In Stage 2, the team defined three core objectives for the Ammar Platform:

* Building user trust through verified company profiles, customer reviews, rating systems, and trust badges.
* Making it easy for users to find the right service provider through search functionality, filtering options, and organized provider profiles.
* Providing a transparent request lifecycle tracking system that allows users to submit and monitor service requests from submission to completion.

The MVP successfully addressed the major requirements related to all three objectives. The platform delivers verified company profiles, a rating and review system, and trust badges as planned. Search and browsing functionality were implemented across all provider types, allowing users to discover and compare service providers effectively. The booking and project tracking workflows were also completed, enabling users to submit requests and monitor progress through defined status stages.

### Key Metrics and Performance Indicators

* The MVP successfully implemented the core Must Have features across 4 development sprints, covering authentication, profile management, service browsing, booking workflows, project tracking, and review functionality.
* The MVP successfully delivered the primary client and company workflows required for the platform's core functionality, providing the essential features needed for users to interact with service providers and manage project requests effectively.
* All 4 sprints were completed within the planned timeline, with each sprint concluding with a review and retrospective session.
* Bug resolution was conducted continuously across sprints, with dedicated frontend and backend fixing sessions in Sprint 4 prior to final delivery.
* Final QA testing confirmed successful frontend-backend integration, stable authentication workflows, and functional role-based interfaces across all implemented pages.

## Lessons Learned

### What Went Well

One of the strongest aspects of the project was the team's organization and collaboration. The team adopted a rotating workflow where two members focused on frontend development while the other two worked on backend development each week. Both groups documented their progress and shared updates to ensure everyone remained aligned.

Weekly meetings were conducted to review completed work, integrate frontend and backend components, discuss challenges, and plan tasks for the following sprint. When urgent issues arose, the team arranged additional meetings on the same day to resolve problems quickly and avoid delays.

Communication was highly effective throughout the project. The team used ClickUp for task management and progress tracking, while WhatsApp was used for quick communication and coordination. GitHub played an important role in organizing development through separate branches and version control, helping the team manage changes efficiently.

### Challenges and How They Were Addressed

One of the main challenges was balancing project responsibilities with university coursework and other personal commitments. To overcome this, the team improved time management, prioritized critical tasks, and maintained regular communication to ensure deadlines were met.

Another challenge appeared during Stage 2, when the project report lacked sufficient detail due to limited prior experience with formal project documentation. After recognizing the importance of thorough documentation during the first sprint, the team revised the report structure and improved documentation quality throughout the remaining stages.

The team also experienced changes in project requirements and objectives during development. As the project evolved, some features and priorities were adjusted to better align with project needs and stakeholder expectations. This required flexibility, continuous planning, and regular discussions to keep the project on track.

Frontend-backend integration presented additional technical challenges, particularly when connecting interfaces with APIs and managing multiple user roles. These issues were resolved through increased communication between members, continuous testing, and regular synchronization during sprint meetings.

### Future Improvements

* Gather stakeholder and user feedback earlier in the development process to validate ideas before implementation.
* Place greater emphasis on documentation from the beginning of the project rather than improving it reactively.
* Allocate dedicated time for testing and quality assurance in each sprint to identify issues earlier and reduce last-minute fixes.
* Conduct more frequent review sessions with stakeholders to minimize requirement changes during development and ensure clearer project direction from the start.
* Improve API documentation updates throughout development to reduce integration delays between frontend and backend components.

## Conclusion

The Ammar Platform project provided valuable experience in software development, teamwork, communication, project management, and problem solving. The successful completion of the MVP demonstrated the team's ability to transform an idea into a functional product while applying collaborative development practices and adapting to challenges throughout the project lifecycle.
